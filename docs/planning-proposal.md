# 2026 금융 AI Challenge 기획서 — 보험금 길잡이 Agent

> 문서 상태: 예선 제출용 최신본
> 기준일: 2026-07-31
> 원칙: 이 문서는 현재 기획의 단일 최신본이다. 구현 범위는
> [기능명세서](./feature-specification.md)와 일치시킨다.

## 1. 서비스 명칭

**보험금 길잡이 Agent**

고령 부모의 보험을 대신 챙기는 가족을 위한 약관 근거 기반 보험금
확인·행동 Agent

## 2. 아이디어 기획 핵심내용

- 보험증권·진료서류·사고 설명을 연결해 사용자가 **확인해 볼 보험금 항목**을
  선별한다.
- 계약일과 상품코드를 기준으로 가입 당시 적용된 실제 약관 버전을 찾는다.
- 정의·지급·면책·제한 조항을 관계 그래프로 함께 탐색하고, 근거 경로가
  끊기면 결론을 만들지 않는다.
- 정보가 부족하면 추정하지 않고 Agent가 필요한 사실을 질문한 뒤 기존
  사건 상태에서 분석을 재개한다.
- 결과를 단순 답변이 아닌 `사건 → 진단 → 담보 → 정의 → 지급 → 면책 →
  필요 서류`의 **Claim Evidence Map**과 Action Pack으로 제공한다.
- 실제 우체국보험 약관과 공공 의료코드를 사용하고, 개인 보험증권·진료문서는
  사용자가 직접 넣거나 비식별 합성 문서로 시연한다.
- AI가 보험금 지급 여부나 금액을 확정하지 않는다. 사람이 근거를 확인하고
  공식 보험사 채널에서 최종 실행하는 Human-in-the-loop 구조다.

## 3. 문제 정의 및 제안 배경

### 3.1 해결할 문제

보험금 미청구는 단순히 “조회 채널이 없어서”만 발생하지 않는다. 금융위원회는
숨은보험금이 발생하는 주요 원인으로 보험금 발생 사실을 알지 못하거나 이자
조건을 오해하는 경우를 들었다. 2026년 7월 발표 기준 찾아가야 할 숨은보험금은
10.3조 원이며, 2025년에만 약 80만 건·3조 2,447억 원이 환급됐다.

보험연구원 조사에서도 보험금 청구 과정의 불편은 반복된다.

- 보험금 청구 절차가 불편하다는 응답: 단일응답 39.7%, 복수응답 52.5%
- 보험금 지급 과정 안내가 부족하다는 응답: 54.7%
- 보험금 지급 내역 안내가 부족하다는 응답: 51.4%

현재 서비스는 계약 조회, 숨은보험금 조회, 실손 청구처럼 이미 확인된
대상을 실행하는 데 강하다. 반면 사용자가 여러 증권과 치료 사실을 대조해
“무엇을 확인해야 하는지” 찾고, 가입 당시 약관의 예외 조건까지 검토하는
작업은 여전히 어렵다.

### 3.2 핵심 고객과 채널

1차 고객은 **고령 부모의 보험을 대신 챙기는 가족 보호자**다. 고령층의
디지털 접근성 문제를 고려하되, 문서 촬영·업로드와 가족 간 확인, 공식 채널
실행을 현실적으로 수행할 수 있는 가족을 모바일·데스크톱 웹의 주 사용자로
설정한다.

이 서비스는 기존 공식 채널과 경쟁하지 않는다. 공식 조회·청구 전에 사용자가
놓친 담보와 준비할 자료를 찾는 **사전 확인 채널**이며, 마지막 단계에서
내보험찾아줌·실손24·보험사 공식 채널로 연결한다.

## 4. 서비스 컨셉 및 차별성

### 4.1 서비스 컨셉

> 보험은 사람이 결정하고, Agent는 놓치지 않게 돕습니다.

보험금 길잡이 Agent는 질문에 한 번 답하는 약관 챗봇이 아니다. 사용자의
보험사건을 목표로 받아 문서를 구조화하고, 정확한 약관 버전과 근거를 찾고,
부족한 사실을 질문하고, 검증된 다음 행동까지 준비하는 **Agentic 금융
업무 흐름**이다.

### 4.2 네 가지 차별성

1. **가입 시점 기준 약관 버전 선택**
   최신 약관이 아니라 상품코드와 계약일에 맞는 적용 약관을 먼저 확정한다.

2. **정의·지급·면책을 잇는 Domain GraphRAG**
   유사 문장 하나만 검색하지 않고 연결 조항을 관계 확장해 반대 근거까지
   함께 검토한다.

3. **근거가 부족하면 멈추는 Agent**
   필수 사실이 없으면 Human-in-the-loop 질문으로 전환하고, 근거가 검증되지
   않으면 `확인 불가`로 종료한다.

4. **답변 대신 Claim Evidence Map과 Action Pack**
   사건부터 조항과 필요 서류까지 도달 경로를 시각화하고, 사용자가 보험사에
   물어볼 질문과 공식 실행 경로를 제공한다.

### 4.3 Agent 구성

- **Case Analyst Agent**: 사용자 목표와 사고·진단·기존 청구 여부 구조화,
  다음 도구 선택, 누락 정보 질문
- **Policy Curator Agent**: 신규 약관 감지, 버전·조항 차이 분석, 지식 그래프
  갱신 후보 생성
- **Evidence Auditor Agent**: 잘못된 버전, 인용 오류, 면책 누락, 근거 없는
  단정 탐지
- **결정론적 도구**: PDF 텍스트 추출, 상품·계약일 파싱, 버전 계산, 검색,
  인용문 존재 검사, 개인정보 마스킹, 출력 스키마 검증

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

### 5.1 실제 데이터

- 우정사업본부 공공데이터포털 `우체국보험 상품별 약관 정보조회 API`
- 우정사업본부 공공데이터포털 `우체국보험 상품별 보장내용 정보조회 API`
- 우체국보험 공시실의 상품코드·판매기간·공식 약관 PDF
- 국가법령정보센터 보험 표준약관
- 건강보험심사평가원 질병정보·수가기준 공공데이터
- 보험사·공공기관의 공식 청구 구비서류와 공식 실행 경로

예선 데모의 기준 사례는 실제 우체국보험 상품코드 `P400073`과 2025년 4월
적용 약관을 사용한다. 합성 증권에는 `무배당 생활재해보장특약Ⅱ 2504` 가입
사실을 포함하고, 합성 진료문서에는 `S52.5` 손목 골절 정보를 포함한다.
Agent는 실제 약관에서 골절 정의, 지급 사유, 동일 사고 1회 지급, 보장개시일
이전 사고와 의학적 골절술 면책, 지급액 표와 질병분류코드를 연결한다.

### 5.2 사용자 데이터

- 사용자가 업로드한 텍스트 레이어 PDF 또는 TXT 보험증권·진료자료
- 사고일, 수술·입원 여부, 기존 청구 여부에 대한 사용자 답변
- 심사용 비식별 합성 보험증권·진료문서

원본은 저장하거나 학습에 사용하지 않는다. 주민등록번호·증권번호 등 직접
식별정보는 파싱 단계에서 마스킹하고 구조화된 사건 정보만 분석 상태에
전달한다.

### 5.3 생성형 AI와 Agentic Workflow

생성형 AI는 자연어 사건 구조화, 검색 질의 보정, 사용자 추가 질문과
Action Pack 문장 생성에 사용한다. 핵심 금융 근거는 모델 기억이 아니라
공식 약관 원문과 구조화 도구에서만 가져온다.

Agent 실행 상태와 조건부 경로는 LangGraph로 관리하고, 문서·검색 도구는
LangChain 호환 인터페이스로 연결한다. Hybrid RAG는 상품·계약일·버전을
하드 필터한 뒤 키워드와 벡터 검색을 결합하고, Domain GraphRAG가
정의·지급·면책·참조 조항을 확장한다. 검색 근거가 불완전하면 Corrective
Retrieval을 최대 1회 수행한다.

최종 출력은 결정론적 인용 검증과 Evidence Auditor 검토를 모두 통과해야
한다. 모델이나 외부 API가 없더라도 버전 선택·근거 연결·안전 상태 분류는
결정론적 경로로 재현 가능하게 설계한다.

## 6. 기대 효과 및 확장 가능성

### 6.1 고객 효과

- 여러 보험계약과 치료 정보 사이에서 놓친 확인 대상을 빠르게 좁힌다.
- 보험사 문의 전에 근거 조항, 미확인 조건, 필요한 서류를 한 번에 준비한다.
- 지급 가능성을 단정하는 잘못된 기대 대신 확인 가능한 사실과 한계를
  구분한다.
- 큰글씨·단계별 한 개의 주 행동·가족 공유 구조로 디지털 접근 부담을 낮춘다.

### 6.2 금융회사와 사회적 효과

- 근거 없는 반복 문의보다 상품·조항·질문이 구조화된 상담 전환을 돕는다.
- 약관 버전과 면책 근거를 함께 제시해 설명 가능성과 소비자 신뢰를 높인다.
- 미청구 가능성의 사전 발견을 도와 포용금융과 금융소비자 권익에 기여한다.

### 6.3 확장

- 우체국보험에서 민간 생명·손해보험 공시약관으로 상품군 확대
- 골절·입원·수술에서 진단·후유장해·중도보험금 등 사건 유형 확대
- 신규 약관 감지 → 조항 Diff → 회귀 평가 → 사람 승인 후 반영하는
  PolicyOps 운영 도구
- 금융상품 설명서, 연금·대출 약정, 공공 복지 수급 조건 등 버전과 예외가
  중요한 다른 문서형 의사결정 지원으로 확장

## 7. 안전성과 검증 가능성을 기능으로 만든 Agent

서비스는 아래 네 상태만 사용한다.

- `확인 권장`: 증권·사건·약관 근거가 연결됐으나 보험사 최종 확인이 필요
- `정보 필요`: 핵심 사실이 없어 사용자 또는 공식 자료 확인이 필요
- `가능성 낮음`: 현재 입력에서 필요한 조건이 확인되지 않음
- `확인 불가`: 버전·근거·면책 검증에 실패했거나 보험사 내부 데이터 필요

심사자는 배포 URL에서 샘플 사건을 실행한 뒤 실제 상품코드, 적용 약관 버전,
원문 출처, Agent별 입력·출력, 근거 그래프, 질문에 따른 분기, Action Pack을
직접 확인할 수 있다. 사용자가 자신의 텍스트 레이어 PDF 또는 TXT를 넣어도
동일한 파이프라인이 작동한다.
