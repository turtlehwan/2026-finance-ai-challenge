# 조사 근거와 1위 전략

이 문서는 기획서의 사실 근거, 유사 대회에서 관찰한 선호 패턴, 실제 데이터
범위와 구현 우선순위를 공유한다. 제품의 최신 제안은
[기획서](./planning-proposal.md), 실제 구현 범위는
[기능명세서](./feature-specification.md)가 단일 진실 원천이다.
심사자 관점의 준비도 판정은 [예선 준비도 보고서](./contest-readiness-report.md),
주장별 출처와 표현 규칙은 [주장·의사결정 근거 대장](./claim-evidence-matrix.md)을
따른다.

## 1. 공식 대회 요구를 제품 요구로 번역

| 공식 요구 | 제품에서 증명할 것 |
|---|---|
| AI 기반 금융 현안 해결 | 미청구 가능성 발견 과정의 실제 불편과 AI의 구체적 역할 |
| 금융소비자 특성과 채널 고려 | 고령 부모를 챙기는 가족 보호자, 웹·공식 채널 연결 |
| 실제 작동 웹서비스 | 샘플뿐 아니라 사용자의 문서도 넣어 작동하는 URL |
| 기획서·기능명세서·배포 URL | 문서와 화면, API 동작을 동일한 범위로 유지 |
| 별도 데이터 미제공 | 출처·이용조건이 명확한 실제 공공·공시 데이터 확보 |
| 상위 약 11팀 발표 심사 | 15분 안에 문제 → 실제 데이터 → Agent 동작 → 안전성 효과를 시연 |

예선 마감은 2026년 9월 7일 10시다. 배포 URL은 9월 7일 11시부터
9월 11일 23시 59분까지 접근 가능해야 하며 접근 불가는 결격 사유다.

## 2. 공식 사실·외부 선례·팀 가설의 분리

현재 공개된 2026 대회 안내에는 제출물과 주제 적합성·부적격 여부는 확인되지만,
세부 배점과 “이 기능이면 1위”라는 공식은 공개되어 있지 않다. 따라서 아래
세 층위를 섞지 않는다.

| 구분 | 이번 문서에서의 의미 | 사용 규칙 |
|---|---|---|
| 공식 사실 | DAKER·금융보안원 공고, 금융위원회·보험연구원·공식 약관이 직접 확인하는 내용 | 수치·일정·제출물·원문 범위를 출처와 함께 기재 |
| 외부 선례 | 2025년 보도된 수상 사례와 다른 평가 트랙의 관찰 | 현재 2026 배점으로 오인하지 않고 설계 참고로만 사용 |
| 팀 가설 | 가족 보호자, 근거 지도, 안전 중단, 실행 trace가 심사 이해를 높일 것이라는 판단 | 효과를 보장하지 않고 URL·사용성·회귀 검증으로 검증 |

따라서 이 프로젝트를 “1위가 보장된 서비스”라고 표현하지 않는다. 정확한 표현은
“공식 요구를 충족하면서 실데이터·실행 과정·안전 경계를 한 번에 검증하도록 만든
상위권 목표 설계”다.

## 3. 전년도 수상 패턴

2025 금융 AI Challenge 대상은 우리은행 직원 4명으로 구성된 AIgency 팀의
`SIGNAL`이었다. 소상공인의 흩어진 매출·순이익 데이터를 모아 위기 상황에서
필요한 행동을 제안했고, 실제 작동 프로토타입과 기술·기획 완성도를 함께
평가받았다.

2025 모델 경쟁에서도 관련 문서를 RAG로 선택하고 신뢰도가 낮은 답변을
제외하는 접근이 성과를 냈다. 역사적 평가 기준에는 표현·논리·문장 완결성뿐
아니라 실제 활용 가능성이 포함됐다.

이를 현재 서비스에 적용하면 다음 순서가 중요하다.

1. 여러 문서와 정보가 흩어진 구체적 생활 문제
2. 공식 실데이터를 실제로 결합
3. 결과가 아니라 **다음 행동**까지 완수하는 동작형 Agent
4. 낮은 신뢰도·근거 누락 시 멈추는 안전 장치
5. 기술 이름보다 전후 차이를 즉시 이해시키는 시각적 데모
6. 기술 완성도와 기획·설명 완성도를 동시에 증명

## 4. 실제 문제와 사람의 불편

### 확인된 사실

- 금융위원회는 2026년 7월 2025년 말 기준 찾아가야 할 숨은보험금이 10.3조
  원이라고 발표했다. 이 수치는 지급금액이 이미 확정된 중도·만기·휴면보험금이며,
  본 서비스가 찾아낼 금액이나 직접 시장 규모로 사용하지 않는다.
- 2025년에는 약 80만 건, 3조 2,470억 원이 환급됐고 건당 평균은 약
  404만 원이었다.
- 금융위원회는 발생 사실을 알지 못하거나 이자 조건을 오해하는 것을 주요
  원인으로 들고, 고령층 대상 오프라인 교육도 추진한다고 밝혔다.
- 보험연구원 2022 조사에서 전체 결과 표본은 보험금 청구·지급 경험이 있는
  19~69세 성인 2,551명이다. 불만족 이유 문항의 응답자 179명 중 보험금 청구
  절차 불편은 단일응답 39.7%, 지급 과정 정보 부족은 54.7%였다.

### 제품 문제 정의

> 사용자는 조회할 공식 채널이 없어서만 멈추는 것이 아니라, 자신의 치료 사실과
> 보험가입증서, 가입 당시 보험약관을 대조해 무엇을 확인할지 정리하지 못해
> 공식 채널에 도달하기 전에 멈출 수 있다.

앞의 공식 통계와 조사는 이 청구 전 확인 공백의 규모를 직접 측정하지 않는다.
미인지와 절차·설명 부담이 실제로 존재한다는 인접 근거이며, 청구 전 확인 공백은
MVP와 사용자 조사로 검증할 제품 가설이다.

가족 보호자를 핵심 사용자로 둔 것은 조사 수치를 과장한 주장이 아니라,
고령층의 접근성 문제와 문서 수집·업로드·공식 실행의 현실적 수행 주체를
결합한 제품 설계 선택이다.

### 5.1 바로 활용 가능한 공식 데이터

| 데이터 | 제공 내용 | MVP 역할 |
|---|---|---|
| 우체국보험 약관 API | 상품명, 적용 시작·종료일, 공식 약관 URL | 계약일 기준 버전 선택 |
| 우체국보험 보장내용 API | 상품별 보장문구·내용·적용기간 | 보장 항목 후보와 이름 정규화 |
| 우체국보험 공시실 | 상품코드, 판매기간, 실제 약관 PDF | 원문 근거와 페이지 인용 |
| 국가법령정보센터 표준약관 | 공통 정의·지급 절차 | 공통 구조 검증 |

| 손해보험협회 소비자포털 | 실손의료보험금 표준 청구서류·간소화 기준 | Action Pack의 공식 서류 안내 기준 |
| 심평원 질병정보 | KCD 질병명·상병코드 | 진단명과 약관 분류표 연결 |
| 심평원 수가기준 | 의료행위 코드·명칭 | 수술·처치 후보 정규화 |
| 공식 구비서류 안내 | 사고 유형별 필요 서류 | Action Pack |

### 5.2 현재 검증된 실제 약관 범위

우체국보험 공시실에서 `무배당 우체국와이드건강보험`의 두 실제 판매 버전을
확인했다.

- `P400051~P400054`: 2021-12-01 ~ 2025-04-02
- `P400073~P400076`: 2025-04-03 ~ 2025-06-04

2025년 4월 약관 PDF의 `무배당 생활재해보장특약Ⅱ 2504`에는 다음이
실제로 포함된다.

- 재해로 골절 상태가 됐을 때 재해골절보험금 지급
- 치아 파절 제외

금융감독원 표준약관 현행 PDF는 국가법령정보센터에서 2026-07-15 시행본으로
확인했으며, 질병·상해보험 구간의 인쇄면 143~149를 구조화했다. 원문 PDF의
SHA-256과 이전 시행본 해시는 `data/policies/manifest.json`에 기록했다. 이
표준약관은 상품별 지급 여부를 대체하지 않고, 상품 약관의 공통 정의·면책·청구
절차가 함께 연결됐는지 검증하는 보조 근거다.
- 보장개시일 전 골절은 미지급
- 같은 재해로 두 가지 이상 골절 시 1회 지급
- 치료 목적의 의학적 골절술은 미지급
- 골절은 재해로 뼈의 연속성이 완전 또는 불완전하게 끊어진 상태
- 특약 보험가입금액 1,000만 원 기준 재해 1회당 10만 원
- 대상 분류표에 S52(아래팔의 골절) 포함

두 버전 모두 골절 지급사유·골절 정의·동일 사고 제한·면책·청구서류·S52 분류표를
페이지 단위로 구조화했다. 여기에 `무배당 우체국온라인입원수술보험 2112`
(`P600107`, 2021-12-01~2025-04-02)를 더해, 주계약의 4일 이상 입원·수술 요건,
입원/수술 정의, 입원일수 제한, 면책, 입원확인서·수술증명서 요건을 실제 원문으로
연결했다.

따라서 아래 세 공식 원문이 현재 결과 근거 범위다.

| 상품·버전 | 상품코드 | 실제 사례 | 검증 조항 |
|---|---|---|---|
| 와이드건강보험 2112 | P400051~054 | S52 골절 | 지급·정의·제한·면책·서류·분류표 |
| 와이드건강보험 2504 | P400073~076 | S52 골절 | 지급·정의·제한·면책·서류·분류표 |
| 온라인입원수술보험 2112 | P600107 | 4일 이상 입원 | 지급·정의·제한·면책·서류 |

### 5.3 공개되지 않는 데이터

- 개인 보험가입증서와 실제 진료내역
- 개인의 기존 청구·지급 이력
- 보험사의 지급심사 결과와 확정 금액

이 영역은 공식 서식 기반 비식별 합성 문서 또는 사용자가 직접 넣는 문서로
처리한다. 서비스는 내부 지급 이력을 추정하지 않고 공식 채널 확인을
요청한다.

## 6. 기술 선택: 라이브러리는 수단, 증명은 화면에서

| 기능 | 재사용할 라이브러리/방식 | 선택 이유 |
|---|---|---|
| 상태·분기·Agent 실행 | LangGraph JS | 중단·재개와 실행 노드가 코드로 검증 가능 |
| 동의형 문서 변환·사실 보조 | Cloudflare Workers AI | PDF·이미지 텍스트화, 마스킹 미리보기의 누락 사실 후보 JSON 생성 |
| Agent 흐름·근거 지도 | `@xyflow/react` | 커스텀 노드, 줌·팬, 동적 상태 표시 |
| 문서 텍스트 추출 | `unpdf` | 서버·브라우저 런타임 호환 PDF 텍스트 추출 |
| 분석 전환 모션 | GSAP + `@gsap/react` | 노드 활성·상태 전환을 맥락 있게 표현 |
| UI 시스템 | shadcn + Lucide | 상태·입력·대화상자의 접근성과 일관성 |

현재 런타임은 Hybrid RAG·임베딩 검색을 수행하지 않는다. 약관의 조·항·호,
상품 버전, 특약, 참조 관계가 명확하므로 도메인 스키마의 결정론적 그래프를
만들고, 상품·버전이 확정된 조항 ID에서 정의·지급·면책 인접 조항만 확장한다.
Workers AI는 동의형 문서 변환과 마스킹된 누락 사실 후보 정리에만 사용하며,
보장 상태·약관 인용·지급 판단에는 사용하지 않는다.

## 7. 데모의 한 문장과 장면

### 한 문장

> 실제 우체국보험 약관과 내가 넣은 보험가입증서·진료문서가 Agent 그래프 안에서
> 연결되고, 어떤 Agent가 어떤 근거로 멈추거나 다음 행동을 만들었는지
> 눈앞에서 확인한다.

### 90초 핵심 장면

1. 실제 공시 출처와 상품 버전 두 개를 먼저 보여준다.
2. 샘플 문서를 불러오거나 사용자의 PDF/TXT를 업로드한다. 스캔 자료는 명시적
   동의 후 AI 문서 변환을 사용한다.
3. Case Analyst가 계약·진단·특약을 구조화한다.
4. Version Resolver가 계약일에 맞는 `P400073 / 2504` 약관을 선택한다.
5. React Flow에서 Agent와 도구 노드가 실제 실행 순서대로 활성화된다.
6. 결정론적 근거 그래프가 골절 정의·지급·면책·분류표를 한 경로로 확장한다.
7. 빠진 정보가 있으면 그래프가 사용자 질문 노드에서 멈춘다.
8. Evidence Auditor가 원문·페이지·버전·면책 동반 여부를 검증한다.
9. 결과 카드와 Claim Evidence Map, 준비 서류·질문이 동시에 나타난다.
10. 사용자가 공식 채널로 이동한다.

## 8. 예선 1위에 가까워지기 위한 완료 기준

- 실데이터라는 사실을 보험사·상품코드·적용기간·원문 URL·페이지로 증명
- 샘플과 사용자 문서 입력이 동일한 실제 파이프라인을 사용
