## 1. MVP 구현 범위

현재 MVP는 공식 우체국보험 상품·약관 버전 데이터와 심사용 비식별 합성
사례 4종을 사용해 다음 범위를 구현했다.

- 상품코드와 계약일을 공식 판매기간에 대조하는 약관 버전 선택 API
- 실제 우체국보험 2개 상품·3개 버전(`P400051~054 / 2112`,
  `P400073~076 / 2504`, `P600107 / 2112`)의 정의·지급·제한·면책·청구서류
  근거 연결
- 국가법령정보센터의 금융감독원 `보험업감독업무시행세칙 별표 15` 현행
  표준약관(2026-07-15 시행)을 provenance·PolicyOps 구조 검토 자료로 공개
- 결과 화면에 보험사·공식 출처·적용일·문서 페이지·SHA-256 provenance를 공개
- 결과에서 공식 약관 PDF의 조항·페이지 원문 링크 제공
- 텍스트 레이어 PDF·TXT 보험가입증서와 진료자료 1~2개 업로드
- 사용자 동의 시 Cloudflare Workers AI로 PDF·JPG·PNG·WEBP 문서를 변환하고,
  마스킹된 미리보기의 누락 사실 후보만 JSON Mode로 보조
- 업로드 문서의 상품코드·계약일·특약·진단코드·사고일·치료 정보 구조화
- 주민등록번호·전화번호·증권번호·이름 표기 마스킹과 원본 비저장
- LangGraph 기반 Case Analyst·Coverage Matcher·Evidence Auditor·Action
  Planner와 전문 도구의 실제 조건부 실행
- 각 Agent·도구의 실제 입력·출력·상태·소요시간 React Flow 시각화
- 사용자 답변 전 Human-in-the-loop 노드에서 중단하고 답변 후 감사 경로 재실행
- 지원 36건·미지원/정보누락 14건의 50건 결정론적 회귀 fixture를 실제 그래프에 실행
- 회귀 fixture 생성 규칙과 분리한 15건 수작업 라벨 holdout을 별도 실행
- 약관 버전 선택·근거 완전성·안전 중단·trace 완결성 회귀 지표와 한계 공개
- 손목 골절, 5일 입원, 오래된 계약, 면책 조건 사례 선택
- 사례의 사고·진단·계약 정보 표시
- 단계별 Agent 분석 진행 상태 표시
- 부족한 사실에 대한 사용자 추가 질문
- 답변을 반영한 제한 상태 결과 생성
- 글 또는 음성으로 요청하면 결과·근거·다음 행동 중 필요한 컴포넌트만 전면에
  배치하는 적응형 보험 확인 비서
- 브라우저 음성 인식 미지원 환경에서도 동일하게 동작하는 텍스트 입력·빠른 요청
- GSAP 전환과 reduced-motion 대체 동작을 적용한 컴포넌트 단위 포커스 전환
- 사용자 주 과업과 분리된 문서 입력·공식 원문·회귀평가·PolicyOps 상세의 기본 접힘
- 사건부터 다음 행동까지의 근거 경로 표시
- 필요 서류·보험사 문의 질문 Action Pack
- 공식 조회·청구 채널 연결
- 14px 최소 글자, 15px 기본 UI 글자, 17px 본문과 큰글씨 모드
- 1440·1024·390·320px에서 가로 넘침 없이 재배치되는 반응형 UI
- PolicyOps 변경 조항 검토·승인 시연

현재 결과는 공식 약관 구조 데이터, 사용자 업로드 문서 또는 합성 사례와
LangGraph 서버 실행을 연결한 동작형 프로토타입이다. React Flow는 API가
반환한 실제 실행 trace를 시각화한다.

## 3. 사용자 이용 흐름

1. 사용자가 배포 URL에 접속한다.
2. 상단의 큰글씨 버튼으로 글자 크기를 선택한다.
3. 네 준비 사례 중 하나를 선택하고 `이 사례 분석하기`를 누른다. 다른 요청이
   필요할 때만 `글이나 음성으로 요청하기`를 펼친다.
4. 지금 필요한 추가 질문 하나에 직접 답하거나 `수술은 안 했어요`처럼 글·음성으로
   말한다.
5. 해석된 선택을 한 번 확인해 제출한다.
6. 답변을 반영한 보장 항목별 상태와 이유를 한 번에 한 항목씩 확인한다.
7. `근거 약관 보여줘`를 요청해 공식 출처·적용일·조항·쪽수를 확인한다.
8. `준비 서류 알려줘`를 요청해 Action Pack과 보험사 문의 질문을 확인한다.
9. 필요하면 `분석 과정` 보기로 실제 Agent trace를 다시 확인한다.
10. `내 문서로 확인하기`를 펼쳐 같은 과정을 자신의 텍스트 레이어 PDF·TXT
    1~2개나 공식 약관 연결 샘플로 이어간다. 스캔 이미지·PDF는 `AI 보조 문서
    이해`를 켠 뒤 명시적 외부 처리 고지를 확인하고 변환한다.
11. 그 뒤 필요할 때 `공식 원문과 검증 결과`를 펼쳐 내부 회귀 50건과 수작업
    라벨 holdout 15건의 네 지표·한계를 확인한다.
12. 공식 채널에서 실제 조회 또는 청구를 진행한다.

## 4. AI 및 데이터 처리 방식

### AI 역할

현재 MVP 서버는 기본 경로에서 사용자 PDF·TXT 텍스트를 추출하고 개인정보를
마스킹한 뒤 상품코드·계약일·가입 보장·진단코드·사고일·치료·입원일수를
구조화한다. 사용자가 `AI 보조 문서 이해`를 켠 경우에는 Cloudflare Workers AI
Markdown Conversion이 PDF·이미지를 텍스트로 바꾸고, 마스킹된 미리보기만
`@cf/meta/llama-3.1-8b-instruct-fast` JSON Mode에 전달해 누락 사실 후보와
짧은 확인 질문을 받는다.

LangGraph 상태 그래프는 Case Analyst, Coverage Matcher, Evidence Auditor,
Action Planner와 Document Tool, Version Resolver, 결정론적 근거 그래프,
Information Gate를 실제로 실행한다. LLM 보조는 LangGraph 시작 전 선택형
문서 이해 도구이며, 보험금 상태·약관 버전·조항 인용·금액을 결정하지 않는다.
각 노드와 선택형 AI 도구의 입력·출력·상태·소요시간을 trace에 남겨 React Flow가
같은 경로를 화면에 표시한다.

상품코드와 계약일을 공식 판매기간에 대조한 뒤, 사례별로 필요한 지급·정의·제한·
면책·청구서류/분류표 근거가 모두 연결되고 공식 원문 URL·페이지 검증을 통과해야
`확인 권장` 결과를 생성한다. 현재 런타임은 임베딩 검색·Hybrid RAG·범용
LLM 기반 약관 검색을 수행하지 않는다. 답변이 없으면 Human-in-the-loop 노드에서
종료하고, 답변이 입력되면 Evidence Auditor와 Action Planner 경로를 새로 실행한다.

### 입력·출력

- 입력: 기본 PDF·TXT 최대 2개, 동의 시 PDF·JPG·PNG·WEBP 최대 2개, 합성 사례 ID,
  추가 질문 답변, 화면 전환용 자연어 요청
- 중간 출력: 마스킹된 미리보기, 구조화된 계약·진료 사실, Agent 실행 trace,
  약관 버전 선택 결과, Evidence Audit
- 최종 출력: 보장 항목별 제한 상태, 근거와 한계, 근거 경로, 필요 서류, 확인 질문
- 사용 데이터: 우체국보험 공식 판매기간·약관 PDF 2개 상품·3개 버전과 코드에
  포함된 비식별 합성 보험·진료 사례
- 평가 데이터: 지원 36건·미지원/핵심 사실 누락 14건의 내부 결정론적 fixture,
  그리고 별도 15건 수작업 라벨 holdout

### 개인정보·민감정보

회원가입이 없고 업로드 원본은 서비스의 서버 파일시스템·데이터베이스·모델 학습에
저장하지 않는다. 파싱 결과를 반환하기 전에 주민등록번호·전화번호·증권번호와
이름 표기를 마스킹한다. 단, 사용자가 AI 보조 문서 이해를 켠 경우 원본 PDF·이미지가
Cloudflare Workers AI 변환 서비스로 전송된다. 이 외부 처리·비저장 범위를 토글
옆에 고지하고, 범용 LLM에는 원문이 아닌 마스킹된 미리보기만 전달한다.
브라우저에는 합성 사례 선택 정보만 저장할 수 있다.

음성 입력은 지원 브라우저의 Web Speech API를 선택적으로 사용한다. 마이크는
사용자가 버튼을 누른 경우에만 시작하며, 음성이 시작된 순간 브라우저 제공자의 외부
인식 서비스 전송 가능성과 서비스 서버의 원문 음성 비저장을 표시한다. 인식된 문장은
클라이언트에서 화면 보기와 제한된 답변 값으로 변환하며 원문 음성을 서비스 서버에
저장하지 않는다. 음성 기능이 없거나 권한을 허용하지 않아도 텍스트 입력과 빠른
요청으로 전체 흐름을 완료할 수 있다.

## 5. MVP 검증 방법

### 검증 절차

1. 배포 URL
   `https://finai26.turtlehwan.dev`에 접속한다.
2. `내 문서로 확인하기`를 펼친 뒤 `공식 약관 연결 샘플 불러오기`를 누른다.
3. `P400073`, `2025-05-10`, `생활재해보장특약Ⅱ`, `S52.5`가 구조화되어
   표시되는지 확인한다.
4. `손목 골절` 사례를 선택하고 `이 사례 분석하기`를 누른다.
5. 기본으로 전면에 나타나는 React Flow에서 Case Analyst부터 Human-in-the-loop까지
   실제 실행 경로와 노드 입력·출력을 확인한다.
6. 질문 화면에서 `수술은 안 했어요`를 입력해 `아니오`가 선택되는지 확인한 뒤
   제출한다.
7. Evidence Auditor와 Action Planner 노드가 추가로 실행되는지 확인한다.
8. 재해골절보험금이 `확인 권장`, 상해수술비와 입원일당이 `가능성 낮음`으로
   표시되는지 확인한다.
9. `근거 약관 보여줘`를 입력했을 때 공식 출처와 조항·PDF 페이지 컴포넌트가
   전면으로 이동하는지 확인한다.
10. `준비 서류 알려줘`를 입력했을 때 Action Pack이 전면으로 이동하는지 확인한다.
11. `면책 함정` 사례에서 `잘 모르겠어요`를 선택한다.
12. 보상 조항만으로 결론을 내리지 않고 `정보 필요` 또는 `확인 불가` 상태가
   나타나는지 확인한다.
13. 큰글씨 버튼과 데스크톱·태블릿·모바일 화면에서 현재 할 일과 결과 보기 흐름이
    유지되고 가로 스크롤이 생기지 않는지 확인한다.
14. `5일 입원` 사례를 선택해 입원 일수 5일을 확인한다. `계속`을 누른 뒤
    P600107 / 2112 버전과 4일 이상 입원 조건, 수술기록 추가 질문이 연결되는지
    확인한다.
15. `AI 보조 문서 이해`를 켜고 비식별 합성 PDF 또는 이미지를 입력한다. 외부
    Workers AI 처리 동의 안내, 변환 결과 또는 안전한 실패 안내가 표시되는지
    확인한다. AI 보조를 끈 경로에서는 텍스트 레이어 PDF·TXT만 처리되는지
    확인한다.
16. 내부 평가 카드에서 결정론적 회귀 50건과 별도 수작업 라벨 holdout 15건,
    실제 지급 정확도가 아니라는 한계 고지를 각각 확인한다.

### 계정과 실행 환경

- 테스트 계정: 필요 없음
- 권장 브라우저: 최신 Chrome, Safari, Edge. 음성 입력은 브라우저 지원 시에만
  활성화되고 텍스트 입력은 공통 지원한다.
- 권장 환경: JavaScript 활성화, 320px 이상 모바일·태블릿·데스크톱

### 예상 결과

- 질문 답변 전에는 결과를 확정하지 않는다.
- 면책 사실을 모르면 지급 가능성을 단정하지 않는다.
- 모든 결과에 이유·한계·다음 행동이 함께 표시된다.
- 최종 지급 여부와 확정 금액은 서비스가 제시하지 않는다.

### MVP 제한사항

- 보험가입증서·진료 문서는 합성이며 보험약관·판매기간은 공식 실제 데이터다.
- AI 보조를 끄면 텍스트 레이어 PDF·TXT만 처리한다. AI 보조를 켜면 PDF·JPG·PNG·
  WEBP를 Workers AI로 변환하지만, 저해상도·손상 문서·복잡한 표는 텍스트화에
  실패할 수 있으며 원문·공식 확인을 대체하지 않는다.
- 내부 50건 지표는 우체국보험 2개 상품·3개 버전의 결정론적 회귀평가다. 별도
  15건 수작업 라벨 holdout은 생성 규칙에서 분리됐지만 두 집합 모두 합성
  사실관계이므로 실제 고객 분포나 보험금 지급 정확도를 대표하지 않는다.
- 범용 LLM·임베딩 검색·Hybrid RAG는 현재 런타임에서 수행하지 않는다. Workers AI는
  동의 기반 문서 변환과 마스킹된 누락 사실 후보 정리에만 사용한다.
- PolicyOps 승인 버튼은 예선 시연 상태만 기록하며 운영 약관 인덱스·지급 규칙을
  자동 변경하지 않는다.
- Web Speech API는 모든 주요 브라우저에서 동일하게 지원되는 기능이 아니며,
  브라우저에 따라 외부 음성 인식 서비스를 사용할 수 있다. 음성은 보조 입력이고
  텍스트가 기본 경로다.
- 보험사의 청구 이력·지급심사·확정 금액을 조회하지 않는다.
- 실제 보험금 지급 여부는 보험회사가 결정한다.
